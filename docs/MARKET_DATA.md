# Market Data Engine

How live and historical market data enters the platform, how it is labelled, and how to connect each supported provider.

## Data flow

```
Broker / vendor ──REST snapshot──┐
                 ──WebSocket────▶ Worker: FeedManager
                                   ├─ validate + merge partial updates
                                   ├─ label (LIVE / DELAYED / HISTORICAL / SIMULATED)
                                   ├─ Redis: latest quote per instrument  ──▶ REST /api/v1/market/*
                                   ├─ Redis pub/sub "ticks"               ──▶ API ──WS /ws/stream──▶ browser
                                   ├─ CandleBuilder → 1-minute bars       ──▶ PostgreSQL candles
                                   └─ health (state, latency, errors)     ──▶ Data Provider Settings, top bar
API (on demand): historical candles → provider REST → stored → served
```

## Labels and timestamps

| Label | Meaning |
|---|---|
| **LIVE** | From the active real provider during market hours, updated within `stale_after_seconds` (default 30s). |
| **DELAYED** | The vendor marks its data as delayed, or a LIVE quote has not updated within the stale threshold (also shown as `STALE`). |
| **HISTORICAL** | Market is closed (last session's data), or stored candles. |
| **SIMULATED** | Generated by the development simulator. Never shown in real mode. |

Every quote carries `source`, `received_at` and, when the provider sends one, `exchange_ts`. The UI shows the label with source and timestamp in its tooltip. Feed latency is the median gap between exchange timestamp and receipt.

## Validation

Quotes are rejected (and counted under *Rejected quotes*) when the LTP is not a positive finite number, any price or volume is negative or non-finite, high < low, the LTP sits outside the day's range by more than 1%, or the timestamp is more than 2 minutes in the future. Candles with inconsistent OHLC are dropped before storage.

## Reliability

- **Reconnection:** exponential backoff with full jitter (1s → 60s cap), reset after two minutes of healthy streaming.
- **Rate limits:** a token bucket per provider (Upstox 20 req/s, Angel One 3 req/s by default; override with `rate_limit_per_sec` in Options). HTTP 429 and 5xx are retried with backoff and `Retry-After` is honoured.
- **Token refresh:** Angel One sessions are refreshed (or re-logged-in with PIN + TOTP) 45 minutes before expiry. Upstox tokens cannot be refreshed; the feed shows `auth_required` once the daily token expires.
- **Market calendar:** NSE session times plus holidays (synced from Upstox, or added manually). Provider-reported market status takes precedence.
- **Isolation:** each worker loop is supervised and restarted on failure; a provider failure never takes down the API.

## Connecting a provider

1. **Data Provider Settings → Add provider**, choose the type and enter credentials. Secrets are encrypted with `SECRET_ENCRYPTION_KEY` and only ever shown masked.
2. **Test connection** authenticates and fetches a sample quote (Nifty 50 by default; override with `test_instrument_keys` in Options).
3. **Sync instruments** downloads the provider's instrument master and maps it to the canonical instrument table (EQ and INDEX; add `"include_fo": true` for F&O).
4. Import an index constituents CSV (for example NSE's `ind_nifty50list.csv`) with index code `NIFTY50`. This sets sectors and the tracked universe.
5. **Activate**. The worker connects and streams the tracked universe: dashboard indices, holdings, watchlists, alert instruments and the tracked index.

### Upstox

- Create an app in the Upstox developer console and set its redirect URL to `https://<your-site>/api/v1/admin/providers/upstox/callback`.
- Enter the API key, API secret and the same redirect URI, then click **Connect Upstox** to log in. Repeat once per trading day; tokens expire around 03:30 IST.
- Feed types: `full` (LTP, OHLC, 5-level depth; up to roughly 2,000 instruments), `ltpc` (LTP only; more instruments), `full_d30` (30-level depth; few instruments).

### Angel One SmartAPI

- Create a SmartAPI app and enable TOTP on the account. Enter the API key, client code, login PIN and the base32 TOTP secret.
- Login, refresh and daily re-login are automatic. Optionally set `client_public_ip` and `mac_address` in Options if your account requires static values.

### Custom REST / WebSocket

For licensed vendors without a built-in adapter. Everything is configured in Options. See the docstring in `backend/app/marketdata/custom.py` for all keys. Example:

```json
{
  "quote_path": "/v1/quotes?symbols={keys}",
  "quote_items_path": "data",
  "quote_map": {"key": "symbol", "ltp": "last", "prev_close": "close", "volume": "volume", "timestamp": "ts"},
  "candles_path": "/v1/candles/{key}?interval={interval}&from={start}&to={end}",
  "candles_items_path": "candles",
  "auth_header": "X-API-Key",
  "delayed": true
}
```
